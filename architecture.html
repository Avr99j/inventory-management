System Architecture

Inventory Management System

A full-stack factory inventory demo built with Vue 3 and FastAPI. This page explains how the pieces fit together — from the browser all the way to the data files.

Technology Stack

Three layers: a Vue 3 frontend, a FastAPI backend, and flat JSON data files.

Frontend

Vue 3 Client

Runs in the browser on port 3000. Built with the Composition API and bundled by Vite for fast hot-reload during development.

Vue 3 Composition API Vue Router Axios Vite
Backend

FastAPI Server

Runs on port 8001. Exposes a REST API, validates data with Pydantic, and serves filtered JSON responses to the frontend.

FastAPI Pydantic Python 3.13 uv CORS
Data

JSON Files

No database. All data lives in server/data/*.json. The server loads everything into memory at startup.

inventory.json orders.json spending.json backlog.json

Filter Data Flow

The most important mechanism in this app. Four global filters (Time Period, Warehouse, Category, Status) update every view simultaneously. Here is exactly how that happens.

1

User picks a filter in FilterBar.vue

The filter bar renders four dropdowns. Each is bound with v-model directly to reactive refs inside the useFilters composable.

2

useFilters composable holds shared state

useFilters.js is a singleton — the refs are declared at the module level, so every component that calls useFilters() shares the exact same state. There is no prop drilling.

const selectedLocation = ref('all') // shared by ALL components const selectedCategory = ref('all') const selectedPeriod = ref('all') const selectedStatus = ref('all')
3

Each view watches the filters and reloads

Every page component sets up a watcher on all four filter refs. When any of them change, loadData() is called automatically.

watch([selectedPeriod, selectedLocation, selectedCategory, selectedStatus], () => { loadData() })
4

api.js builds a query string and calls FastAPI

The centralized API client converts the filter object into URL query parameters. Values equal to 'all' are omitted so the backend returns unfiltered data.

GET /api/orders?warehouse=San+Francisco&category=circuit+boards&month=2025-01
5

FastAPI filters the in-memory data and responds

The backend applies apply_filters() (warehouse, category, status) and filter_by_month() sequentially on the in-memory list and returns the result as JSON. Quarter shortcuts like Q1-2025 expand to three months.

6

Vue re-renders with new data

The response is assigned to a reactive ref. Vue's reactivity system detects the change and updates the DOM. Computed properties that derive KPIs and chart data recalculate automatically.

Key Design Patterns

Non-obvious decisions worth understanding before making changes.

●

Singleton Composable State

useFilters.js declares its refs outside the exported function, at module scope. This means all components share one instance — changing a filter anywhere updates every view simultaneously without a global store like Pinia.

●

Raw Refs + Computed Properties

Components store raw API data in ref() (e.g. allOrders) and derive everything else with computed(). Computed values are cached and only recalculate when their dependency refs change, avoiding unnecessary work on every render.

●

In-Memory Filtering (No Database)

The server loads all JSON into Python lists at startup via mock_data.py. Filtering is list comprehensions in plain Python. There is no database connection, no ORM, and no persistent writes — a deliberate choice to keep the demo simple and portable.

●

Localization Without a Library

useI18n.js implements a minimal i18n system in ~130 lines. It stores the locale in localStorage, maps locale to currency, and provides specialized translators for product names, customer names, and warehouses — all without an external dependency.

●

Backlog Filters via Client-Side Cross-Join

The backlog API has no filter params. Instead, the frontend fetches all backlog items and all filtered inventory items, then keeps only backlog entries whose SKU appears in the filtered inventory set. This avoids adding filter logic to the backlog endpoint while still respecting warehouse/category filters.

●

Custom SVG Charts (No Chart Library)

All charts — donut, bar, horizontal bar — are hand-drawn SVG inside Vue templates. They use computed() to transform data into path coordinates. This keeps the bundle lean and gives full control over appearance without learning a chart library API.
